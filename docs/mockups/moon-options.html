Decisions to take before building

  1. 1Which layout — A (month chart + table), B (night ribbons), C (window finder), or C on top with A or B folding open beneath it (recommended: C + A).
  2. 2Thresholds — LOW < 25% / HIGH ≥ 60% are planning defaults (Army aviation NVG training minimums sit near 23% with the moon ≥ 30° up). Editable on the card and kept per browser, or declared once in the Mission Profile for the whole crew?
  3. 3Night definition — nautical twilight (EENT→BMNT, the OPORD standard) as drawn, or civil / astronomical as a switch. The astro module today computes sunrise/sunset and civil twilight; nautical is one more zenith angle.
  4. 4Moonrise / moonset are NEW maths — the app has synodic illumination only (good to a few hours); rise/set and moon altitude need a low-precision lunar position (Meeus) + an iterative horizon crossing. Pure, tested, no dependency; minute-grade is planning-grade, not almanac-grade, and the card will say so.
  5. 5Moon altitude — add "moon ≥ 30° above the horizon" as the second condition (a 90% moon on the horizon lights nothing), shown as a dimmer segment near rise/set?
  6. 6Where it lives — a card under Places on the Weather tab (follows the selected place), plus a "Lunar" line on each airfield card and a one-line "tonight: 96% · moon up all night · HIGH" on Glance's Where-you-are. SITREP already has sun/moon; it would read the same module.
  7. 7Export — a zero-JS light-data table (BMNT · SR · SS · EENT · MR · MS · % · moon-free dark h) for 30 nights, the same discipline as the SITREP export, for the OPORD annex.
  8. 8Cloud cover — overlay the Open-Meteo cloud forecast on the next 7 nights (a full moon under overcast is a dark night)? The tab already fetches it.
