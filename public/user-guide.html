DEAD's Dashboard — User Guide

Strategic intelligence dashboard · all features & settings

Getting started

DEAD's Dashboard is a personal intelligence cockpit — seven tabs and a handful of top-bar buttons. It pulls news, Gmail, Google Calendar and Tasks, market data, weather, OSINT feeds, and your own working notes into one screen, then layers AI on top to triage, summarise, and act on everything you see. Single user, single instance: it learns you over time, and every Claude call is gated by toggles you control.

First-time sign-in

  1. Open the dashboard URL and click Sign in with Google. You'll grant access to Gmail, Calendar, and Tasks scopes.
  2. The dashboard opens on the News tab by default. RSS feeds start loading immediately; Gmail and Calendar populate as their scopes resolve.
  3. Open ⚙ (top right) to set your role, topics, timezone, and location. Everything personalises off this — see the Settings tab.
  4. Optional: connect a secondary Gmail account from Preferences for a second inbox.

Five tabs across the top, four action buttons in the header. All tabs stay mounted in the background, so tab switching is instant and the fetches needed for each tab continue in parallel.

Quick wins after sign-in

  • Set your Role / Context in Preferences — every AI response will personalise off this.
  • Type one Watchlist keyword (e.g. hypersonic) — articles mentioning it get an ⚑ WATCH badge and float to the top.
  • Press ⌘K / Ctrl+K from anywhere to capture a thought into a task, calendar event, or memory note.
  • Click ◆ Brief to generate today's morning brief — synthesised from your loaded news + newsletters.

The seven tabs

The seven top-of-app tabs each serve a different daily workflow. Switch with the tab bar; all seven stay mounted so their data refreshes in the background.

01News

The news tab fuses three streams: an RSS feed across ~20 outlets (defense, strategic, domestic, space, local for your area), newsletter summaries pulled from your Gmail, and a Threads / History view that surfaces cross-article narratives.

Sub-tabs (top of tab content)

  • Feed — articles + newsletters. Default view.
  • Threads — Claude finds 4-8 cross-cutting narratives across today's articles ("Russia/Ukraine", "China deterrence", etc.) and writes a short summary + trend (▲ rising / ◆ stable / ▼ fading).
  • History — past Threads sessions saved in the database.

Category filter pills

Above the feed: All · Overview · Defense · Strategic · Domestic · Space · Local · Saved. Each pill shows a count. Saved = articles you starred.

Newsletter section

Appears above the article grid. Newsletters from Politico, Dow Jones War, Merge, and ASF — auto-summarised into bullets by Claude. Click any card to expand. The newsletter open also feeds the ranking algorithm so series you actually read float higher.

Refresh affordances

The ↻ button (top-right of section) refreshes every feed. Refreshes inside the cache window are nearly instant.

02Email

AI-triaged unread inbox across primary + secondary Gmail accounts. Every unread email gets a priority (High / Medium / Low) and a 1-2 sentence summary from Claude. Sorted by priority.

The action-items panel (top of page)

A separate Claude call extracts concrete "you need to do X" items from your unread mail. Each row has a checkbox (mark locally complete) and a + Task button.

Clicking + Task pushes a Google Task to your default tasklist, titled with the action, due date attached if Claude detected one, and notes containing the sender + subject. Button flips to ✓ Added when accepted.

Suggested VIPs (when present)

Above the action items: senders you've replied to ≥3 times in the past 30 days that aren't already classified. Two actions: Add VIP (forces future mail from them to High) or Dismiss (never suggest again).

Filter pills

Above the inbox: All · High · Medium · Low.

Check the box on any card. A bottom bar appears with Mark read and Clear selection. Reads remove the UNREAD label in Gmail and drop the card from the list.

03Calendar

Agenda view of upcoming events (next 30 days, all your Google calendars) plus a right rail with Tasks and an AI scheduling assistant.

Agenda view

Grouped by date. Today, Tomorrow, then weekday names. Click any event to expand:

  • Location, description, account.
  • Attendee list: shown as 👤 emails.
  • 📋 Prep button when the event has attendees — see the next subsection.

Meeting prep panel (📋 Prep)

Click 📋 Prep on an event with attendees. The dashboard runs a Gmail search from:"<attendee>" newer_than:60d for each attendee in parallel and renders the 3 most recent emails per attendee inline. Use this for last-minute meeting context.

Results are cached server-side for 1 hour, keyed by the sorted attendee list, so re-clicking Prep on the same meeting is instant.

Right rail — Tasks

Your Google Tasks default list. Inline create, edit, complete, delete. Tasks created via + Task on the Email tab or via ⚡ Capture show up here in real time.

Right rail — Scheduling chat (rail)

Claude with full read access to your calendar + tasks + recent news + memory. Ask things like:

  • "What's my morning look like Thursday?"
  • "Find me 45 min between 2 and 5 PM tomorrow."
  • "Add a 30 min sync with the planning team next Tuesday at 0900."
  • "Create a task to file the trip report by Friday."

When you ask to schedule or add a task, Claude emits a [ADD_EVENT:…] or [ADD_TASK:…] action block; the UI catches it and executes via the Calendar / Tasks API.

Apple Calendar / iCal feed

In Preferences → Apple Calendar / iCal Feed you'll find a session-authenticated URL that subscribes any iCal app to your upcoming events.

04Docs

A personal markdown wiki for your analytical notes. Distinct from the AI assistant's long-term memory — this is your persistent working surface.

Layout

  • Left sidebar: search box, pinned section, all docs sorted by recency. Click a row to open.
  • Centre: title input, tag chips, pin star, markdown editor on the left, live preview on the right (toggle with ◫ Split / ▭ Edit).
  • Footer: backlinks panel — every doc that [[wiki-links]] to this one shows up as a clickable chip.

Wiki linking

Type [[Doc Title]] in any doc; the preview renders it as a button. Click in the preview to jump there (or create it on the fly if the title doesn't exist yet). Backlinks resolve automatically on save.

Save-to-notes from News

Every article card has a ▤ button next to the bookmark star. Click → creates a new doc with the article quoted, source/date metadata, link, and a ## Notes section ready for annotation. The article id is stored as a backlink edge.

Chat context

The chat assistant sees your 5 most-recently-updated docs (800 chars each) in its system block — ask "what did I write about PLARF last week?" and Claude can cite your note.

Search

Sidebar search uses MySQL FULLTEXT for queries ≥3 chars; LIKE for shorter. Snippets shown per result.

Autosave

1.2 s after you stop typing. Status indicator next to the title: Editing… → Saving… → ✓ Saved → Updated 12 s ago.

Configuring feeds

Add RSS/Atom URLs in Preferences → OSINT Feeds. Suggested URL templates:

  • X account: https://rsshub.app/twitter/user/USERNAME
  • Telegram channel: https://rsshub.app/telegram/channel/NAME

SSRF safety

URL inputs are validated on write and re-validated server-side at fetch time. Loopback / RFC-1918 / link-local hostnames and URLs with embedded credentials are rejected.

Reliability

Per-feed 8 s timeout so one slow source can't block the batch. 5 min server-side cache per feed. If a feed stops loading, swap to a different rsshub instance — the OSINT input is generic, any RSS/Atom URL works.

06Markets

Defense-industry-focused market data: editable ticker watchlist, indices, energy & metals, and the DOD daily contract awards feed.

Custom watchlist

Add tickers in Preferences → Markets Watchlist in TradingView's EXCHANGE:TICKER format (e.g. NYSE:KTOS, NYMEX:CL1!, FX:USDJPY). Up to 30. Default is the 5 primes (LMT/RTX/NOC/GD/BA).

Layout

  • Ticker tape at top — indices + your watchlist (top 6).
  • Market overview with three tabs: Watchlist / Indices / Energy & Metals. Click any symbol for a chart.
  • DOD contract awards — parsed from defense.gov's RSS. Branch badge (ARMY/NAVY/USAF/USMC/Space Force/DLA/MDA), dollar-amount formatted (B/M/K), click-to-expand for the full release link.

07Weather

Multi-location forecasts, NWS active alerts, NOAA SWPC space weather, and a Windy.com map for the selected location.

Multi-location grid

Each tracked location gets a compact card with current temp, wind, short forecast, and the next 4 forecast periods. Severity-coloured alert chip if NWS has an active alert. Click a card to centre the map below.

Add locations in Preferences → Tracked Locations (up to 10). CONUS gets full forecast + alerts; OCONUS coords show "unavailable" (NWS US-only) but still pull alerts if any reach NWS.

Active alerts panel

Aggregates NWS active alerts across every tracked location, deduped (one alert may cover multiple tracked locations) and sorted by severity. Click to expand for full areaDesc + expiry time.

Space weather card

Three blocks: Kp index with a small sparkline of the last 24 h, G-scale geomagnetic storm level (G0–G5), X-ray flare class (A/B/C/M/X) with its derived R-scale radio blackout. Operational note in the footer (HF degradation, SATCOM impact).

Map controls

Overlay selector (Wind / Rain / Temp / Clouds / Pressure) drives the Windy.com ECMWF embed. Map centres on whichever location card is selected; refresh re-loads everything.

METAR quick links

Bottom-of-tab strip of ICAO codes for common CONUS + OCONUS military airfields, plus a SIGMET link. Opens metar-taf.com in a new tab.

The top bar

Four buttons in the header, always available from any tab.

◆ Brief — Morning Brief

Opens the briefing modal. Claude (Opus) synthesises a structured morning brief from the currently-loaded articles, newsletter highlights, and your calendar:

  • Headline — one sentence on the day's most important development.
  • Schedule — time-sensitive items from your calendar.
  • Key developments — top 3 with context.
  • Top stories — 2-3 stories worth a deeper read.
  • Connections — paragraph noting cross-domain patterns.
  • Suggested focus — recommended actions or reading.

◈ Digest — Weekly Digest

Opens the same modal in digest mode. Claude (Sonnet) summarises your reading patterns over the past week — sources you opened most, topics you saved, recommended adjustments to your interests.

⚡ Capture — Quick capture

Opens the quick-capture modal. Also bound to ⌘K / Ctrl+K from anywhere. Type one short thought — Claude routes it into a Google Task, a calendar event, or a memory note, and shows you the parsed plan before committing.

Two-step flow

  1. Type your thought. Examples:
    "remind me to email RAND about the panel next Thursday at 2"
    "team sync tomorrow 0900-0930"
    "save that the Q3 brief is due 12 Aug"
  2. Press ⌘↩ or click Preview. Claude classifies and returns a parsed plan:
    "About to add · Calendar event — Team sync — Wed, May 28, 9:00 AM → 9:30 AM"
  3. If correct, press ⌘↩ or click Confirm — the action commits. If wrong, click Edit to return to the input with your text preserved.

Watchlist — Keyword alerts

Tag input of bare keywords. Any article title or newsletter bullet containing one gets an ⚑ WATCH badge and floats to the top of its section.

Email Triage Overrides

Per-sender forcing of the email priority. Two lists:

  • Always High — VIP Senders: mail from these is forced to High regardless of Claude's judgment.
  • Always Low — Muted Senders: forced to Low (still shown, just demoted — not hidden).

Each entry is either a full email address (boss@company.com) or a bare domain (example.com). Domain rules also match subdomains.

Applied after Claude classification at merge time, so you get Claude's summary text either way — the priority is just forced.

Tracked Locations — Weather tab

Extra locations shown on the Weather tab alongside your home location. Inline editor below the existing Local Area select: label + lat/lon. Each gets a forecast card, active NWS alerts, and feeds the alerts aggregator. Up to 10.

The home location (from Local Area above) is always shown first; tracked locations follow.

Markets Watchlist — Markets tab

TradingView symbols rendered as the first tab of the markets overview widget plus an extension to the ticker tape (up to 6 entries on the tape). Inline add/remove editor: symbol (EXCHANGE:TICKER) + display label.

Default is the 5 defense primes — overwrite with your own list when you save changes for the first time.

OSINT Feeds — OSINT tab

Inline editor for RSS/Atom feeds powering the OSINT tab. Each entry: label, URL, kind (social / telegram / news / other). The kind determines which OSINT pane the feed appears in.

URLs are validated client-side at write and server-side at fetch against an SSRF-block list (loopback / RFC-1918 / link-local / embedded credentials all rejected). Only HTTP / HTTPS.

Usage display

Live card at the bottom of the panel:

  • Today's spend: total USD spent on Claude calls since local midnight, plus call count.
  • Last 7 days / Last 30 days: rolling totals computed in your timezone.
  • Today's breakdown (expandable): per-route spend with the count of calls. Lets you see which feature is driving cost.

Logging is fire-and-forget — a DB failure can never break the user-facing response. Per-token rates live in lib/aiFeatures.ts and need a manual update when Anthropic publishes new pricing.

Long-term memory

A markdown document the assistant maintains about you across chat sessions. View the current contents, edit manually, or Clear all.

The dashboard updates this in the background after chat turns — debounced to ~5 minutes between updates so a long conversation consolidates into a single update. Each turn's content goes onto a persisted queue until the gap elapses; nothing is lost.

Quick-capture notes append under a ## Notes section here too.

What's new — features added this push

Major features added to the dashboard. Roughly chronological by ship order; each one has stable behaviour and lives in production today.

#1Newsletter summarisation upgrade

Switched the newsletter summarisation model from Haiku 4.5 to Sonnet 4.6. Eliminates the empty-bullet failure mode where Haiku would occasionally drop items from large batched JSON arrays, leaving you with "No key facts extracted." Bounded cost by the existing 7-day cache.

#2Email triage cache + personalised prompt + VIP / mute lists

Three changes around inbox triage:

  • Classification cache. Every email is classified once and stored by message id with the prompt's hash. Subsequent refreshes inside 30 days reuse the cached priority + summary — instant render, no Claude call. The hash invalidates the cache automatically when you edit your interests.
  • Personalised prompt. The triage prompt now includes your role, priority topics, deprioritise topics, and watchlist — Claude knows what counts as "an important institution" for you.
  • VIP / mute lists. See Settings → Email Triage Overrides. Deterministic post-classification override.

#3Persistent memory layer

A long-running markdown document about you that survives across chat sessions. After each chat turn, a Haiku call consolidates the conversation into the document — capturing ongoing projects, upcoming events, named contacts, and ad-hoc preferences. Injected into chat, briefing, and quick-capture as background context.

The consolidation is debounced (≥5 min between updates) with a persisted queue, so a burst of chat collapses to one Claude call but no content is lost mid-window.

#4Action items → Google Tasks

Extracted action items on the Email tab now each have a + Task button that pushes a Google Task to your default list. Title = action, due date = parsed deadline (if any), notes = the source email's sender + subject.

#5Quick capture (⌘K)

Global keyboard shortcut. One textarea, one Claude call, three destinations: task, calendar event, or memory note. Two-step preview-then-confirm flow means nothing commits to your calendar or Tasks until you OK the parsed plan.

#6Implicit feedback on articles + newsletters

Every article title click and newsletter expand feeds a small positive signal into the ranking model (~¼ of an explicit thumbs-up). After a week or two of normal use, the news feed starts privileging sources you actually open. Newsletter ordering already used this signal; we extended it to articles.

Client-side dedup keeps repeat clicks in a 7-day window from multi-boosting the same article.

#7"What changed since I last looked"

A per-surface last_seen_at snapshot. When you reload the dashboard, items older than your snapshot render at 50-60% opacity (hover restores). Eyes get drawn to what's new. Applies to:

  • Email cards
  • News cards
  • Newsletter cards

The snapshot bumps to "now" after 5 seconds of dwell on a tab. The newsletters surface only bumps when you actually expand a newsletter, so viewing the news tab without scrolling down doesn't falsely mark newsletters as seen.

#8Suggested VIPs from reply patterns

The dashboard scans in:sent newer_than:30d in your primary account and surfaces senders you've replied to ≥3 times that aren't already classified. Cached server-side for 12 hours so the scan is cheap after the first call of the day.

#9Quiet-newsletter suggestions

Newsletter series whose open_count is 0 (never expanded) are surfaced in a small prompt above the newsletter section. One click hides the whole series from future loads.

#10Cached morning briefing

Generated briefings persist in MySQL keyed by YYYY-MM-DD in your timezone. Re-opening Brief during the day returns the cached version instantly with no Claude call. The ↻ Refresh button in the modal busts the cache when headlines shift materially.

#11Meeting prep auto-context

Calendar events with attendees get a 📋 Prep button. Clicking it runs a Gmail search per attendee in parallel and renders the 3 most recent emails from each inline. Cached server-side for an hour, keyed by the sorted attendee list.

#12DEAD POOL skull-reticle favicon

Custom favicon: a stylised skull centred inside a red tactical targeting reticle on a slate-950 background. Pure SVG, scales cleanly from 16×16 (browser tab) to 128×128 (bookmark).

#13Weather tab buildout

Multi-location dashboard (up to 10 tracked locations), aggregated NWS active-alerts panel, and a NOAA SWPC space-weather card showing Kp index with sparkline, G-scale geomagnetic storm level, and X-ray-flare-derived R-scale radio-blackout level. #14Markets tab buildout

#15OSINT tab (new)

Sixth tab. Six panes — All / Social / Telegram / News / Aircraft / Maritime. Aggregates user-configured RSS/Atom feeds and embeds ADS-B Exchange + MarineTraffic centred on your home location. URL inputs are SSRF-validated (loopback / RFC-1918 / embedded credentials all rejected).

#16Documents / Notes tab (new)

Personal markdown wiki, separate from the AI assistant's memory. Sidebar list with FULLTEXT search, pin + tag, autosave with indicator, split-view markdown editor with live preview. Wiki linking via [[Doc Title]] with auto-resolved backlinks. "Save excerpt to Docs" button on every news card. Chat assistant sees your 5 most-recently-updated docs as background context.

#17AI Controls

Master kill switch + per-feature toggles for direct control over every Claude API call the dashboard can make. Live "today's spend" card with last-7 / last-30 totals and per-route breakdown. Per-token rates hardcoded in lib/aiFeatures.ts driving a logged anthropic_usage table. Streaming routes capture token counts from message_start + message_delta events.

#18Docs editor upgrades

Three editor improvements landed together: keyboard shortcuts (⌘B bold, ⌘I italic, ⌘K external link, ⌘[ wiki-link), a slash-command palette (type / at the start of a word for /h2, /task, /code, /today, etc.), and interactive task lists — - [ ] and - [x] render as clickable checkboxes in the preview and flip the source marker on click.

#19OSINT clustering + AI triage

Near-duplicate headlines across feeds collapse into one cluster with a +N more from {feed A}, {feed B} expand. The OSINT relevance scoring toggle adds a priority pill (High / Medium / Low) to each cluster based on role / topics / watchlist / AOR, with the reason carried on the pill's hover title. 14-day cache keyed by a prompt hash that invalidates whenever your context changes.

#20Per-doc chat (💬 Ask)

On any document, the new 💬 Ask button in the doc header opens a chat panel scoped to just that doc — Claude can only cite what's written there (plus your background context). Useful for quick "summarize this in 3 bullets" or "what are the open questions?" passes without losing the doc you're reading. Conversation state is per-doc and resets on switch.

#21Capture into Docs from anywhere

The save-to-Docs button (▤) — already on news cards — now also appears on email cards and OSINT cluster cards. Each creates a doc tailored to its source:

  • Email card → doc: sender / account / date header, AI summary if present, body preview as a blockquote, and a ## Notes section. The email message id is recorded as a backlink (type: email). Tag: email.
  • OSINT cluster → doc: primary item title / source / feed kind / date, an Also seen in: list of the dupe feeds (so the corroboration count survives), the triage call inline if scored, link, summary blockquote, and a ## Notes section. Tags: osint + the feed kind.
  • Action item → tracking doc: new ▤ Doc button next to the existing + Task in the action-items panel. Generates a doc with ## Status (Open / In progress / Done as a task list), ## Subtasks, and ## Notes. Source email recorded as backlink. Tags: tracking + action-item.

Same idle / saving / saved / error UX on every button. The Docs editor footer also grew a word count + chars + ~N min read strip so you can see at a glance how long a note has gotten.

Under the hood — optimization & cost

The features above ship with their own performance work. Summary of the optimization decisions, what they save you, and the audited impact on Claude API spend.

Caching layers

CacheScopeTTLSaves
email_classification_cache Per-message Gmail id × prompt hash 30 days One Claude triage call per new email instead of per fetch.
briefing_cache Per date × user timezone 7 days (pruned) One Opus briefing call per day instead of per modal open.
newsletter_cache Per Gmail message id 7 days One Sonnet newsletter summarisation per new email.
vip_suggestions_cache Per Google account 12 hours Up to 200 Gmail metadata calls per email-tab open.
In-process message cache Per (account, message id) 10 minutes Up to 50 Gmail full-fetch calls per dashboard refresh.
In-process meeting-prep cache Per sorted attendee list 1 hour Up to 32 Gmail calls per Prep re-click.
Anthropic prompt cache Per stable system block Ephemeral ~90% of input-token cost on warm reads (chat, gmail, briefing, newsletters).

Gmail-traffic hygiene

  • Chunked concurrency. Bulk Gmail metadata pulls (VIP scan, meeting prep) use a worker-pool of 10 concurrent calls instead of an unbounded Promise.all burst — keeps requests under the 250 quota-units/sec/user limit.
  • Body-preview trimming. Email bodies sent to Claude for classification are stripped of standard signature blocks, mobile sigs, and long quoted-reply chains, then capped at 400 chars (down from 800). ~60% reduction in input-token spend per cold classification with no measurable quality regression.
  • Atomic prefs append. VIP/mute/dismissed-suggestion writes go through a dedicated /api/user-prefs/append endpoint that uses JSON_ARRAY_APPEND with a JSON_CONTAINS idempotency guard in one SQL statement — race-safe with other concurrent prefs edits.

Troubleshooting

"Your session needs to be refreshed"

Sign out and sign back in. The Google OAuth token expired and a scope or refresh-token state needs to reset.

Newsletter card shows "No key facts extracted"

Should be rare since the Sonnet swap. If it happens, refresh — the cache only stores summaries that had bullets, so an empty result isn't sticky.

Briefing modal shows nothing / empty fields

Click ↻ Refresh. Empty-field cases now return a 502 instead of caching — but a server hiccup mid-stream could still produce an unusable brief. Refresh forces regeneration.

VIP suggestion that I dismissed keeps reappearing

The dismiss endpoint is atomic and idempotent, so this shouldn't happen. If it does, the dismissed list may be at its 500-entry cap and rotating out old entries — adjust the cap in app/api/user-prefs/append/route.ts if you need more.

Quick capture commits the wrong thing

The preview step exists exactly for this. Click Edit on the preview to return to the input with your text intact, then refine the phrasing. Common fixes: add an explicit time for events; use "remember that…" to force a memory note.

Items that should be dimmed aren't (or vice versa)

The "last seen" snapshot is captured at page-load and stays fixed for the session. Reload the page to capture a fresh snapshot, or bump the column to 0 in surface_state to reset.

Glossary

TermMeaning
Surface One of email, news, or newsletters — a tab/section the user scans for new content. Tracked separately for the "what changed" feature.
Prompt hash A short hash of the system prompt + user context. Drives cache invalidation for email triage. Changes when you edit your interests.
VIP override A deterministic post-classification priority forcing. VIP wins over mute if a sender somehow matches both.
Ephemeral cache (Anthropic) A prompt-caching mode where the first call writes the cache and subsequent calls within the cache window read at ~10% of normal input cost.
